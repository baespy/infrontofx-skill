# Handoff

เขียนบันทึกส่งต่อเมื่อจบเซสชัน ก่อน context เต็มหรือถูกบีบอัด เมื่อหยุดกลาง resource หรือเมื่อเจ้าของพิมพ์ "สรุปส่งต่อ" หรือ "handoff" เป้าหมายคือเซสชันใหม่ทำต่อได้ทันทีจากบันทึก โดยไม่ต้องอ่านแชตเดิม

## ที่เขียน

`PROGRESS.md` ของเจ้าของ อยู่ที่ราก `<project>` นอก repo ของชุดนี้ ถ้ายังไม่มีให้สร้าง เพิ่มต่อท้ายเสมอ ไม่เขียนทับของเดิม และไม่เขียนความคืบหน้าลง `SKILL.md`

## แม่แบบ

```markdown
## <YYYY-MM-DD> <หัวข้องาน>

- เปลี่ยน: <ผลที่ผู้เล่นหรือเจ้าของเห็น หนึ่งถึงสามบรรทัด>
- ไฟล์: <resource>/core/sv_main.lua, <resource>/html/js/app.js
- backup: _backup/<YYYY-MM-DD>/<resource>
- ตรวจแล้ว: lint 0 error(s) exit 0, สัญญาเทียบ backup ไม่มี <=, resmon ในโซน <ก่อน> ms -> <หลัง> ms
- ต้องลองในเกม: 1) <การกระทำ> -> <ผลที่ต้องเห็น> 2) ...
- ค้างให้เจ้าของตัดสิน: <คำถาม> แนะนำ: <คำตอบ>
- ตัดสินใจเอง: <อะไร> เพราะ <เหตุผล> ถ้าผิดเสีย <อะไร>
- สถานะ: เสร็จ | ค้างที่ขั้น <n>/<ทั้งหมด> (แก้ <ไฟล์> แล้ว, ยังไม่ได้รัน lint)
- ขั้นถัดไป: <การกระทำเดียวที่ทำได้ทันที> ใช้ <โหมดหรือ skill ที่ต้องเปิด>
```

กติกา:

- ชี้ไปที่ไฟล์ ไม่คัดลอกโค้ดลงบันทึก
- ของจริงตรงทุกตัวอักษร: พาธ ชื่อ event และ export ตัวเลขพร้อมหน่วย ข้อความ error
- secret ห้ามลง บอกแค่ตำแหน่งไฟล์ ไม่ใส่ข้อมูลส่วนตัวของผู้เล่นหรือที่อยู่เซิร์ฟเวอร์
- งานค้างกลาง resource บอกให้ชัดว่าไฟล์ไหนแก้แล้ว ไฟล์ไหนยัง และ backup ยังเป็นสภาพก่อนเริ่มงานหรือไม่
- บรรทัด checkpoint ระหว่างทางจาก `references/plan.md` รวมเป็นรายการเดียวตอนปิดงาน
- "ขั้นถัดไป" ต้องเป็นการกระทำที่ทำได้เลย ไม่ใช่ "ทำต่อ" หรือ "ตรวจอีกรอบ"

## อะไรไปที่ไหน

| ข้อมูล | ที่ |
| --- | --- |
| ความคืบหน้า บทเรียนต่อ resource ผลวัด หนี้เทคนิค | `PROGRESS.md` ของเจ้าของ |
| พฤติกรรมของ engine, native, exploit หรือ pattern ที่ใช้ได้ทุกเซิร์ฟ | `memory/` ของ infrontofx |
| คำสั่งใหม่ของเจ้าของที่เป็นกฎถาวร | `SKILL.md` ของ infrontofx หรือของ sub-skill ที่เกี่ยว |
| ความชอบและการตัดสินใจเฉพาะโปรเจกต์ | ความจำส่วนตัวของผู้ช่วย ไม่ลง repo สาธารณะ |
| secret, ข้อมูลส่วนตัว, ที่อยู่เซิร์ฟเวอร์ | ไม่บันทึกที่ไหนเลย |

เขียนที่เดียว ห้ามซ้ำสองที่ ตามกติกาความจำในไฟล์ `TOOLING.md` ของ infrontofx

## เมื่อไรลง memory/ ของ infrontofx

ลงเมื่อครบทั้งสามข้อ:

1. เป็นข้อเท็จจริงที่ยืนยันแล้ว ทำซ้ำได้ หรือเจ้าของยืนยันในเกม ไม่ใช่ข้อสงสัย
2. ใช้ได้กับเซิร์ฟ FiveM อื่นด้วย ไม่ผูกกับ resource หรือข้อมูลของเซิร์ฟนี้
3. ไม่มี secret ชื่อคน หรือพาธของเครื่อง

เลือกไฟล์ตามชนิดของเรื่อง:

| เรื่อง | ไฟล์ของ infrontofx |
| --- | --- |
| native และพฤติกรรมของ engine | `memory/native-gotchas.md` |
| ช่องโหว่และวิธีปิด | `memory/security-exploits.md` |
| แพตเทิร์นที่ใช้ซ้ำได้ | `memory/patterns.md` |
| ผลวิจัย perf ที่มีแหล่งอ้าง | `memory/performance-research.md` |

ทุกรายการต้องมี `Date:` และ `Game build:` ตามรูปแบบใน `memory/README.md` เพื่อให้ปลดทิ้งได้เมื่อ FXServer หรือ game build เปลี่ยน ค่า game build ใช้ค่า `sv_enforceGameBuild` ใน `server.cfg` ถ้าไม่ได้ตั้งไว้ ให้เขียนว่าเป็นค่าเริ่มต้นพร้อมเวอร์ชันของ FXServer
